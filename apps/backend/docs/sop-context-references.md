# SOP 上下文料号引用

## `0 OT3 assemble B SOP-20260331.pdf` 调试结论

这份 PDF 的文件名和内容对应 OT3 Flex / Assembly SOP。逐页检查后：

- 第 62 页的 `920-00118` 出现在红框文字说明中；照片标注 `920-00083`、`920-00084`、`920-00085` 也是 PDF 内的可提取矢量文字，不是纯图片像素。
- 第 82 页的 `415-00376` 出现在红框文字说明中。
- 这些料号都出现在 instruction 页面，不在显式 `Material List` 页面。因此它们属于上下文引用，不属于 `bom_materials`。

原流程在工作流选择某个工序为“仅识别 SOP BOM 清单”时，只读取 `bom_materials`，会因此丢弃 instruction 页面上的上下文料号。现在改为：显式 BOM 仍是已列料号的数量权威来源；对 BOM 中没有的料号，补入 `full_text_references`，并标记数量说明为“使用 SOP 上下文引用（非物料清单页）”。已存在于 BOM 的料号不会用上下文引用再次累加。

## 文本框和图片标注的识别策略

1. **文字层优先**：使用 `pypdf` 提取普通文本和 layout 文本。料号正则前先修复 PDF 文本对象常见的 `920-\n00118`、`920 - 00118` 和相邻无分隔料号 `920-00112920-00113`。
2. **来源分层**：保留 BOM 表料号、上下文引用料号、页码和原文证据，避免把“出现过”误当成“新增装配数量”。
3. **纯图片 OCR**：如果未来 PDF 的标注只有像素而没有文字层，再增加可选 OCR（推荐 300 DPI 渲染 + Tesseract `eng`/`chi_sim` 或云视觉服务），只把高置信度且符合料号格式的结果作为候选，和文字层按页坐标/料号去重，并在 UI 中标记 OCR 来源供人工确认。

当前模块没有默认启用 OCR，因为这份调试 PDF 的标注已经是矢量文字；启用 OCR 反而可能把照片中的数字、尺寸和序号误报成料号。
